# Identify membrane response from clamped textile strips

The strip workbench fits the existing cloth membrane by repeatedly solving the actual strip between
two grips. It accepts total grip forces and prescribed grip separation, allows the strip interior to
contract and shear, and compares the resulting reactions with source observations. This makes the
retained production-knit measurements usable for inverse experiments without declaring that an entire
clamped swatch deforms uniformly.

The result is a bounded model estimate. A passed numerical experiment does not establish garment fit,
independent biaxial accuracy, recovery, wrinkling or a textile's missing bending/contact properties.
This guide provides the source acquisition and worked examples; the
[strip calibration workbench guide](clamped-strip-calibration.md) also covers browser controls and
the shared CLI/WASM interface.

## Commands and outputs

Build from the repository root:

```sh
cargo build -p ftx-cli --bin ftx --bin ftx-materials
```

| Operation | Companion command | Output |
|---|---|---|
| Validate and expose original source observations | `ftx-materials strip-acquisition ACQUISITION.json` | Source identities, complete force histories, geometry and optional original transverse curves |
| Predict a declared membrane in a grip fixture | `ftx-materials strip-experiment REQUEST.json` | Frozen material request, equilibrium states, reactions, local strain ranges and solver residuals |
| Identify scalar coefficients or amplitudes of declared nonlinear shapes | `ftx-materials calibrate-strip REQUEST.json [--allow-estimates]` | `calibration` report, conditional exact material selection and separate garment readiness |

The same actions are available as `ftx materials ACTION FILE.json --json`; their report is inside
the ordinary `ftx-cli/1` envelope's `result`. The companion writes the report directly as JSON to
standard output. These commands do not alter the input files.

For `calibrate-strip`, `--allow-estimates` controls admission of fitted output properties and overrides
`input.allow_estimates` in the effective recorded request; omission leaves that permission false.
Estimated acquisition observations still require the separate JSON permission
`allow_estimated_observations`. Estimated nonlinear shapes require their own
`response_family.allow_estimated_shapes` permission. `strip-experiment` uses its material selection's estimate policy,
and `strip-acquisition` does not infer or admit a constitutive law.

The calibration command returns an envelope containing `calibration`, `selection`, exact
`selection_json`, and separate `simulation_ready` / `mechanics_refusal` fields. A completed inverse
operation may return `calibration.accepted: false` and no selectable material: inspect that field
and `calibration.reasons`, not only the shell exit status. Malformed source/input, exhausted work or
failed equilibrium can instead return a runtime refusal. Forward and acquisition commands retain
their direct typed reports.

## Run the complete synthetic identification example

The checked-in [synthetic request](../examples/strip-identification/synthetic-calibration.json) was
generated by the actual strip solver using known coefficients `[300, 180, 0.2, 70]` in the documented
warp/weft/Poisson/shear order. Every force and width is marked `estimate` with an explicit synthetic
source. There is no real textile, inferred fiber identity or physical replicate in this example.

```sh
target/debug/ftx-materials calibrate-strip \
  examples/strip-identification/synthetic-calibration.json --allow-estimates > /tmp/strip-report.json

target/debug/ftx-materials strip-experiment \
  examples/strip-identification/synthetic-forward.json > /tmp/strip-forward-report.json

python3 - <<'PY'
import json
r = json.load(open("/tmp/strip-report.json"))["calibration"]
print("accepted:", r["accepted"], "parameters:", r["parameters"])
print("domain replay:", r["domain_replay_verified"], "remaining reasons:", r["reasons"])
PY
```

The example identifies all four known coefficients and publishes an estimated material after the
declared gates pass. FIT contains warp, weft and bias at 4% and 8% grip extension; each state supplies
force plus material-midpoint width. CHECK is a separately computed warp state at 3%. That separation
exercises the software partition contract but supplies no independent empirical validation. The
2×2 fixture is compared against 4×4 refinement, and the source-locked fitted material is replayed
with its enforced domain. `synthetic-forward.json` is a self-contained replay of the resulting frozen
selection at the two warp FIT extensions.

Regenerate the observations directly from the current production solver, without a separate physics
formula or hand-transcribed output:

```sh
cargo run -p ftx-drape --example strip_fixture > /tmp/new-synthetic-strip-request.json
target/debug/ftx-materials calibrate-strip /tmp/new-synthetic-strip-request.json --allow-estimates \
  > /tmp/new-synthetic-strip-report.json
```

The [generator](../crates/ftx-drape/examples/strip_fixture.rs) declares its known coefficients, fixture,
controls, analysis date, weights and bounds. It emits the public `ftx-strip-calibration/1` schema.
The returned material contains only the four identified membrane properties. Missing density,
bending, thickness and friction remain missing, so this successful membrane example still cannot
be presented as a complete garment material.

## Identify amplitudes of declared nonlinear shapes

The same `ftx-strip-calibration/1` request can include an optional `response_family` with
`model: "scaled_piecewise_linear/1"`. It supplies three existing `StressCurve` objects named `warp`,
`weft` and `shear`, plus `allow_estimated_shapes`. Each curve retains its `points`, `source`,
`evidence`, `method` and `conditions`; source keys resolve in the input material. The curve points
are **material-frame Green strain and second-Piola sheet resultant in N/m**, not grip extension and
total force. Each supplied signed curve includes a stress-free `[0,0]` origin and strictly increasing
strain/resultant knots on both sides of zero. The family uses the existing piecewise-linear material
response, with its analytically integrated energy and coupled-tangent stability checks.

Directly reusing curves from an earlier calibration as the three shape inputs is currently refused.
A shape carrying `fitted_green_strain_range` or a recognized calibration source reference belongs to
a prior four-component law, including its coupling and joint domain; the three-curve declaration
does not retain that complete group. Removing its domain field does not make a recognized calibrated
source independent. Supply separately authored shape evidence or an explicit modeling assumption.
This limitation is separate from replacing an existing material: its complete nonlinear law and
fitted support remain in `material` and constrain the replacement fit.

With a family present, the four entries of `parameter_bounds` and `calibration.parameters` mean:

| Position | Parameter | Unit |
|---|---|---|
| 0 | Positive warp shape scale | dimensionless |
| 1 | Positive weft shape scale | dimensionless |
| 2 | Positive shear shape scale | dimensionless |
| 3 | Signed constant normal coupling | N/m |

For supplied shape functions `w`, `f` and `s`, the identified law is:

```text
S11 = warp_scale * w(E11) + normal_coupling * E22
S22 = weft_scale * f(E22) + normal_coupling * E11
S12 = shear_scale * s(2 E12)
```

Only those amplitudes and coupling are fitted. Knot locations, branch shapes and interpolation stay
as declared. This lets an independently characterized or explicitly assumed nonlinear family enter
the actual grip experiment without a second constitutive engine. It does not learn arbitrary curve
shapes, certify unexcited compression/shear behavior or turn the supplied shape prior into a measured
property. The output remains a conditional model estimate, even when the acquisition forces are
measured. The scalar parameter order elsewhere in this guide applies only when `response_family`
is absent.

Every candidate must be stable over the full declared shape domain, and the entire parameter box
must satisfy the worst-case coupling bound. Shape support and any inherited material support constrain
searches and replay; the published range is further restricted by FIT states. CHECK does not select
shapes, coefficients, knots or strain support. Keep a shape's preparation independent of CHECK:
fitting a shape to all observations first and later relabeling some of them as CHECK does not reserve
independent evidence.

`response_family.allow_estimated_shapes: true` explicitly admits estimated input shapes. It neither
admits estimated acquisition observations nor authorizes consumption of the fitted output. The latter
still requires the ordinary CLI `--allow-estimates` flag or the explicit WASM output-policy argument.
No family is selected from a fiber name, a catalog brand or an incomplete source curve.

### Run the synthetic nonlinear identification and replay

The [nonlinear request](../examples/strip-identification/synthetic-nonlinear-calibration.json)
uses explicitly assumed signed shapes and known generating parameters `[1.1, 0.9, 1.2, 40]` in the
family order above. All forces and material-midpoint widths are recomputed by the public production
strip experiment. FIT has warp, weft and bias states at 2%, 6% and 10% extension; CHECK is a separately
computed warp state at 4%. The shape prior and both partitions are synthetic software data.

```sh
target/debug/ftx-materials calibrate-strip \
  examples/strip-identification/synthetic-nonlinear-calibration.json --allow-estimates \
  > /tmp/nonlinear-strip-report.json

target/debug/ftx-materials strip-experiment \
  examples/strip-identification/synthetic-nonlinear-forward.json \
  > /tmp/nonlinear-strip-forward-report.json

python3 - <<'PY'
import json
r = json.load(open("/tmp/nonlinear-strip-report.json"))["calibration"]
print("accepted:", r["accepted"], "domain replay:", r["domain_replay_verified"])
for parameter, value in zip(r["parameter_descriptors"], r["parameters"]):
    print(parameter["id"], value, parameter["unit"])
print("remaining reasons:", r["reasons"])
PY
```

The accepted result is an ordinary estimated piecewise-linear membrane with support restricted to
FIT, not four scalar stiffness properties. The standalone forward request embeds its exact frozen
selection and replays the three warp FIT extensions. Final predictions and residuals use the doubled
mesh and actual published law, including its clipped domain endpoints; refinement diagnostics compare
those results with the declared mesh. Missing mass, bending, thickness, friction and thermal properties
remain missing.

Regenerate every nonlinear observation with the
[production-solver generator](../crates/ftx-drape/examples/strip_nonlinear_fixture.rs):

```sh
cargo run -p ftx-drape --example strip_nonlinear_fixture > /tmp/new-nonlinear-strip-request.json
target/debug/ftx-materials calibrate-strip /tmp/new-nonlinear-strip-request.json --allow-estimates \
  > /tmp/new-nonlinear-strip-report.json
```

The generator reuses the scalar example's fixture declarations, partitions and numerical controls;
it replaces every force, width and source description. The signed shape nodes, scales and coupling
are declared in its source. It does not derive a nonlinear family from the empirical Sperl curves.

## Use the retained real production-knit observations

The acquisition file contains the original force CSVs for **SJ1, SJ3 and DKIN8**, each cut in warp,
weft and bias directions. It retains the complete source metadata and MIT notice. The optional
transverse section adds the corresponding original contraction CSVs and dataset README. No supplier
SKU, lot equivalence or property shared by all polyester/elastane fabrics is inferred.

```sh
target/debug/ftx-materials strip-acquisition \
  crates/ftx-pattern/src/material_catalog/knit-strip-measurements.json \
  > /tmp/knit-acquisition.json

python3 examples/strip-identification/prepare_sperl.py /tmp/sj1-strip-request.json \
  --workbench target/debug/ftx-materials

target/debug/ftx-materials calibrate-strip /tmp/sj1-strip-request.json \
  > /tmp/sj1-strip-report.json
```

Use new output paths. The preparation helper refuses to overwrite its destination. It calls the
public source parser and catalog resolver, selects exact author loading rows at grip extensions
0.1, 0.2 and 0.3, and retains the SHA-256 and original CSV line in each observation ID. Warp and weft
cuts supply six FIT states; the entire bias cut supplies three held-out CHECK states. `--specimen SJ3`
and `--specimen DKIN8` select the other retained specimens without substituting their data into SJ1.

The helper supplies an explicitly declared exploratory parameter box and residual budgets. Those
settings are analysis choices, not measured material bounds or instrument uncertainty. It does not
fit coefficients, relax a failing gate or admit estimated output properties. Real-knit results may
fail identifiability, the stated approximation, refinement or numerical convergence. A refusal is
useful evidence of the remaining problem; it is not a newly calibrated textile card.

The checked workflow's SJ1 request completes with `calibration.accepted: false`. With the supplied bounds and
50 iterations per start, all three starts remain unconverged and the best candidate hits the
Poisson/shear bounds. Refined force RMS errors are approximately **0.211 N for FIT** and **0.619 N
for CHECK**, exceeding the declared 0.05 N RMS budget; the held-out bias states also leave the
FIT-only strain domain. No material, selection or `selection_json` is published. These diagnostics
describe this bounded attempt; they do not establish a globally optimal fit or license changing
the acceptance budgets until the data appear to pass.

### What the source establishes

[Sperl et al. (2022), section 4.3 and Figure 4][paper] describe a 100 mm free gauge, excluding the
clamped regions, and a 60 mm initial width. Two ends are clamped and stretched horizontally under
displacement control while force is measured. Source angles are **weft 0°, bias 45°, warp 90°**.
The article analyzes loading from rest to 5 N; the retained author CSVs include complete loading and
unloading histories, including higher-force rows and small negative values. The source adapter keeps
those observations intact rather than clipping force or silently discarding a branch.

The author [dataset README][dataset] specifies fractional elongations and compressions. Accordingly:

| Source quantity | Meaning and units | Inverse input |
|---|---|---|
| `elongation` | `(current grip separation / initial free gauge) - 1`, dimensionless | `extension_fraction`, e.g. `0.2` for 20% |
| `force` | Signed total grip reaction, N | `force_n`; never a modulus or an N/m resultant |
| Force CSV `tag` | Original `loading` or `unloading` branch | Select and retain the intended elastic loading observations; do not average branches |
| Transverse `compression` | `1 - deformed width / initial width`, dimensionless | Preserved as `compression_fraction`; no automatic inverse-width mapping |

The source does not provide test rate, timestamps, relative humidity, conditioning duration,
replicate identities, instrument uncertainty, measured clamp slip/compliance or preprocessing
details for these retained rows. Those fields remain explicitly unreported.

The transverse files have no branch tags or spatial sampling coordinates. Figure 4 sketches width
near the swatch center; it does not establish the exact material points or image-sampling line used
under bias shear. The solver's `mid_width` is specifically the distance between opposite side-edge
**material points at half the original gauge length**. The adapter therefore preserves the original
contractions but does not assert that they are this same observable. Resolve the measurement operator
before supplying an empirical `mid_width`; a missing width does not mean zero lateral contraction.

The parser checks independently pinned source hashes, full metadata bytes, license, archive entries,
specimen/cut identity, dates and row ordering. Rehashing altered rows does not make them accepted
author data. Known subsets are supported. The original force-only acquisition remains supported when
the optional transverse fields are absent. The full raw fixture is read from the supplied file and
is not compiled into ordinary catalog/browser binaries.

## Describe the actual fixture

Strip coordinates use **x across width and y along the loading direction**. A fixture is:

```json
{
  "gauge_length_m": 0.1,
  "width_m": 0.06,
  "warp_axis": [0.0, 1.0],
  "cells": [2, 4]
}
```

`warp_axis` is a unit vector in those strip coordinates: `[0,1]` loads along warp/wale, `[1,0]` along
weft/course, and `[sqrt(0.5),sqrt(0.5)]` describes the 45° cut. JSON requires the corresponding numeric
components. The adapter also exposes the paper's original angle convention so the two coordinate
conventions are not silently conflated.

The model fixes both in-plane coordinates at each complete grip edge, prescribes the moving grip's
axial position, constrains all out-of-plane displacement, and solves the remaining in-plane degrees
of freedom with the production cloth Newton solver. It uses unit compression factors, zero bending,
zero gravity and no contact. A positive auxiliary mass is present only to satisfy the cloth storage
invariant; the static calculation never consumes it or reports it as a measured density.

Planarity, quasi-static elasticity and ideal no-slip grips are explicit approximations. This model
does not recover wrinkling, grip slip, clamp compliance, rate dependence, hysteresis or permanent set.
Each extension is an independent equilibrium, not a timed loading step. Existing material relaxation
or permanent-set laws cannot be silently used with an unspecified duration or discarded by the fit.

Cell counts are even. Forward fixtures allow 2–32 cells per dimension and at most 512 cells. Inverse
fixtures allow at most 16 per dimension and 128 total so that doubling each direction stays within
the forward limit. These meshes are starting discretizations, not claims of convergence; every
inverse report compares its selected solution with the doubled mesh.

## Write an inverse request

`ftx-strip-calibration/1` takes the actual specimen `material`, `method`, `conditions`, `fitted_on`,
`experiments`, `parameter_bounds`, `policy` and permissions. Each experiment supplies a unique
acquisition ID, fixture, source key, evidence class, one partition and observation rows. The helper
above emits the complete current schema rather than a separate import format.

An observation has this shape:

```json
{
  "id": "SJ1/warp/0f60fa0dbc3f99bcd0f0ba19c41f6988d7e8931bbfc6790003e12b326bddf0b6/line-102",
  "extension_fraction": 0.2,
  "force_n": 1.06,
  "scale_n": 0.05,
  "mid_width": null
}
```

This is the retained SJ1 warp loading row at 20% extension, with an explicitly chosen weighting
scale. `scale_n` is a positive residual weighting scale in newtons, not an inferred
measurement uncertainty. A supplied `mid_width` has `value_m` and `scale_m`, both in metres, and must
correspond to the material-point distance defined above. Do not turn missing traction, rate or width
observations into zero values.

All selected states from the same acquisition belong to one partition. Reserve independently
acquired cut or fixture observations for empirical CHECK; renaming selected rows of the FIT curve
does not create independent evidence. Reusing the same source reference, dimensions and direction
across partitions refuses even if acquisition labels or mesh counts differ. Synthetic CHECK is only
a separate numerical computation and never evidence of an independent physical replicate.
Different construction, finish, lot, temperature, moisture and rate conditions require
separate source qualification rather than combining specimens into one apparent material response.

Without `response_family`, `parameter_bounds` uses the scalar order:

```text
[warp stiffness N/m, weft stiffness N/m, major Poisson ratio, shear stiffness N/m]
```

The whole box must be positive-definite, including its most adverse combination of endpoints:
`max(abs(nu))² * max(weft stiffness) / min(warp stiffness) < 1`. Bounds are explicit and finite;
the algorithm does not repair an invalid box. At least four FIT scalar channels are required, but
counting four values does not guarantee independent excitation of four coefficients.

The permissions serve different purposes:

| Field | What it authorizes |
|---|---|
| `admit_planar_elastic_model` | Use of the declared planar, ideal-grip elastic experiment model |
| `allow_estimated_observations` | Estimated input observations, including explicitly synthetic solver outputs |
| `response_family.allow_estimated_shapes` | Estimated supplied nonlinear shapes, independently of acquisition and output permissions |
| `allow_estimates` | Admission of resulting estimated properties through the returned material selection; the CLI flag or WASM boolean supplies the effective value |

`replace_existing` separately permits replacement of existing equilibrium evidence. A declared
nonlinear family may replace scalar coefficients or an existing nonlinear response while retaining
the prior compiled and fitted strain limits. Scalar-only calibration still refuses to replace a
nonlinear response, and existing history laws cannot be silently discarded. The complete prior
input remains in the result for review.
The native `strip::fit::calibrate(&input)` API uses the input's output-consent setting directly;
`material_calibrate_strip(input, allowEstimates)` and the CLI record their explicit output policy in
that same input. This never grants permission for estimated acquisition observations.

## Read the acceptance report and reuse an accepted material

The four unknowns are fitted through the actual clamped geometry. Three deterministic bounded local
searches use FIT observations only. CHECK does not choose coefficients, starts, minima or the fitted
strain range. Publication requires converged searches, an interior best candidate, sufficient local
sensitivity, no equivalent separated minima found by those starts, a held-out CHECK acquisition,
acceptable FIT/CHECK residuals and acceptable doubled-mesh prediction changes. Final publication
also replays the candidate through the production forward solver with its fitted strain domain
enforced, for each observed coarse and refined state.

These are numerical/model gates, not statistical confidence intervals or proof of a global optimum.
`starts`, `excitation_pivot`, `fit`, `check`, `mesh_change_peak_scaled`, `predictions`, `forward_solves`,
`domain_replay_verified` and `reasons` expose what happened. States include total grip reactions,
free-force and grip-balance residuals, energy, local Green-strain ranges, deformed positions and
iteration counts.

When `calibration.accepted` is false, the selectable output is null. When it is true, fitted quantities
still have `evidence: "estimate"`, and the material selection retains the caller's estimate policy. An accepted
fit with effective `allow_estimates: false` remains unavailable to consumers that require admission
of these estimated stiffnesses. The envelope's separate `simulation_ready` field also accounts for
missing mass, bending, thickness and contact properties.

The returned `selection_json` is the exact serialized frozen selection. Save that string intact for
binding; its embedded digest protects the normalized record. For a direct companion report:

```sh
python3 - /tmp/strip-report.json /tmp/strip-selection.json <<'PY'
import json, sys
result = json.load(open(sys.argv[1]))
report = result["calibration"]
if not report["accepted"] or result.get("selection_json") is None:
    raise SystemExit("No accepted material: " + "; ".join(report["reasons"]))
with open(sys.argv[2], "x") as out:
    out.write(result["selection_json"] + "\n")
PY

target/debug/ftx-materials bind YOUR-PATTERN.json /tmp/strip-selection.json NEW-PATTERN.json
target/debug/ftx-materials resolve NEW-PATTERN.json
```

The fitted Green-strain envelope is built from FIT elements on the refined mesh plus explicitly
solved undeformed states. Ordinary material resolution retains that range in every selected piece's
grain frame. Strain-domain checks prevent unrestricted extrapolation; CHECK never widens the range.
An axis-aligned range box does not establish accuracy at every combined strain inside it. CHECK
states outside that FIT-only range block publication instead of expanding the supported domain.

When replacing an already fitted material, every objective evaluation, sensitivity probe, trial,
coarse/refined FIT or CHECK state and final replay also retains the inherited source strain limits.
The new range is the intersection of that prior support and the new FIT envelope; the inherited
domain must admit the exact undeformed reference. `replace_existing` permits coefficient replacement,
not broader strain authority. An exploratory search state outside that support can refuse even when
the original fitted selection itself replays successfully. No refit silently expands the source domain.

Mass, unloaded thickness, directional bending, body/self/interface friction, thermal response and
manufacturing properties remain separate observations. A strip-only material can run this membrane
experiment while ordinary garment drape still refuses missing mechanics. Do not fill those gaps with
the source's unknown-pressure gauge thickness or with values from an unrelated textile. A complete
qualified material can enter the normal same-pattern substitution path once its missing consumers'
requirements are satisfied.

## Scope of empirical validation

The original paper explicitly says that these strip data approximate uniaxial deformations and lack
biaxial response information. Its fitted thin-shell law augments anisotropic Saint Venant–Kirchhoff
elasticity with explicit area terms `kn1 * (J - 1)^2 + kn2 * (log J)^2`, where `J` is the area ratio,
because an unaugmented law can invert within tested knit stretches. The authors fit both force and
transverse contraction across all three cut directions. Neither this workbench's scalar fit nor its
separable nonlinear shape family implements those area terms. Positive curve tangents alone do not
establish accurate transverse contraction or general biaxial response. Good synthetic recovery proves
the software identification path; real-source residuals test the declared approximation.[^scope]

The [authors' supplementary document][supplement] reports fitted six-parameter thin-shell models for
SJ1, SJ3 and DKIN8. Shapes derived from those fitted coefficients already depend on the original
all-direction observations. A later bias CHECK from the same source therefore cannot be described as
independent of that shape prior. The released [dataset][dataset] explorer only loads and plots the
source curves; it supplies no additional spatial width operator. This workbench does not select a
nonlinear family automatically from those source measurements or from the published fit coefficients.

Independent matched-specimen bending/contact data and real dressed-garment evidence remain necessary
for broader claims. More raw fabric records, including datasets whose redistribution terms are not
yet established, should be acquired and qualified before becoming bundled empirical properties.
